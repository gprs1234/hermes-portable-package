# FIX_VERIFICATION_STANDARD — 修復驗證標準

版本: v1.0
日期: 2026-05-06
觸發: Arena env var 補齊但未觸發補位事件

---

## 核心原則

**修復的驗收標準是「問題消失」，不是「動作完成」。**

---

## 一、定義

### 動作完成 (Action Complete)
- 我執行了一個操作
- 例: 寫入了 env var

### 問題消失 (Problem Resolved)
- 原本報告的問題不再出現
- 例: 策略補位成功，deficit 下降

### 差距
- Action Complete ≠ Problem Resolved
- 中間可能還有 1~N 步需要執行

---

## 二、修復流程（強制）

```
1. 偵測問題
   └→ 記錄: 問題是什麼、根因是什麼

2. 找到修復方法
   └→ 記錄: 需要哪些步驟、每步的依賴關係

3. 列出完整步驟鏈（不只第一步）
   └→ 例:
      a. 設 env var
      b. 確認 env var 名稱與 consumer 匹配
      c. 觸發 consumer (generator / plan_agent / etc)
      d. 驗證 consumer 成功執行
      e. 驗證問題消失 (deficit 下降)
      f. 驗證下一次自動巡邏報告正確

4. 執行所有步驟（不只是第一個）

5. 驗證問題消失
   └→ 如果沒消失 → 回到步驟 2
   └→ 如果消失 → 報告完成

6. 報告完成時必須包含:
   - Before 狀態
   - 執行了哪些步驟
   - After 狀態
   - 問題是否消失
   - 如果沒消失，卡在哪
```

---

## 三、反模式（禁止）

| 反模式 | 正確做法 |
|--------|---------|
| 「設好了，等它自己跑」 | 設好 → 立刻觸發 → 驗證 |
| 「第一步完成了，報告完成」 | 所有步驟完成才算完成 |
| 「env var 存在 = 問題解決」 | env var 存在 + consumer 成功 + 結果正確 |
| 「我做了 X」 | X 導致了 Y 結果，Y 已驗證 |

---

## 四、適用範圍

- 任何修復操作（不只是 env var）
- 任何「補齊」操作（補 key、補 config、補檔案）
- 任何「設定」操作（設 cron、設 webhook、設路由）
- 任何涉及「A 設好 → B 才能跑」的依賴鏈

---

## 五、驗證 Checklist 範本

修復完成後必須回答：
- [ ] 原問題還存在嗎？
- [ ] 如果存在，卡在哪一步？
- [ ] 如果不存在，是什麼導致問題消失的？
- [ ] 下一次自動巡邏會報告正確嗎？
- [ ] 有沒有引入新問題？
